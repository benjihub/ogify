# Ogify discoverability launch checklist

## Included in this patch
- Unique page titles, descriptions, and canonical URLs for the documentation pages.
- `robots.txt` generated by Next.js with a sitemap URL and a private-dashboard crawl exclusion.
- A curated sitemap that excludes the noindex status page and does not claim every URL changed on every request.
- Organization, website, and software-application JSON-LD structured data.
- `noindex` metadata for sign-in, sign-up, and service-status pages.
- `/llms.txt` as a compact directory for AI-assisted discovery. It is supplementary; it does not replace normal indexing.

## Do after deployment

### 1. Google Search Console
1. Open Google Search Console and add a **Domain** property for `ogify.online`.
2. Verify ownership using the DNS TXT record Google provides. Add that exact record in the DNS provider; do not share verification tokens publicly.
3. Submit `https://ogify.online/sitemap.xml` in the Sitemaps section.
4. Use URL Inspection on the homepage, `/docs/quickstart`, `/docs`, `/open-graph-image-api`, `/website-screenshot-api`, and `/pricing`.
5. Test the live URL, then request indexing for the most important public pages. Indexing is not guaranteed and can take time.

### 2. Bing Webmaster Tools
1. Add `https://ogify.online` to Bing Webmaster Tools, or import the verified site from Search Console if available.
2. Submit `https://ogify.online/sitemap.xml`.
3. Check crawl/indexing diagnostics after the first crawl.

### 3. Check the deployed output
- `https://ogify.online/robots.txt` returns HTTP 200 and points to the sitemap.
- `https://ogify.online/sitemap.xml` returns valid XML and contains the public pages.
- `https://ogify.online/llms.txt` returns HTTP 200.
- Each public page has one self-referencing canonical URL on `https://ogify.online`.
- The canonical host remains `ogify.online` (not `www.ogify.online`).
- The homepage social image `https://ogify.online/og-image.png` loads publicly.
- Search crawlers can access the documentation without signing in.

### 4. Publish genuinely useful developer content
Prioritize a small number of complete tutorials over dozens of thin keyword pages:
1. Generate Open Graph images in Next.js using Ogify.
2. Capture a full-page website screenshot with TypeScript and cURL.
3. Convert HTML to PDF through a rendering API.
4. Generate social preview images in a CI/CD workflow.
5. Compare template rendering, URL screenshots, and branded composite cards with runnable examples.

Each tutorial should include tested code, a real output example, limitations, a canonical URL, and links to the relevant API reference. Avoid duplicating the same landing-page copy across multiple URLs.

### 5. Build credible discovery signals
- Make the GitHub repository description and README clearly identify `https://ogify.online` as the official website and describe Ogify as a screenshot, PDF, and social-image rendering API.
- Ensure npm/package metadata links to the canonical site and repository.
- Submit a truthful listing to relevant developer directories and launch communities; do not mass-post or buy backlinks.
- Share a useful tutorial with runnable code in developer communities rather than posting a generic product advertisement.

## Important brand note
Search results for the name “Ogify” also surface similarly named products and repositories. Consistently use the descriptor **“Ogify API — website screenshots, PDFs, and Open Graph images”** in titles, repository descriptions, package metadata, and launch listings so people can distinguish this product. Search Console is needed to confirm actual indexing; a normal search result alone is not a complete index report.
